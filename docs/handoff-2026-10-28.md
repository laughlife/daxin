## 一、三项（已完成）

### ① 品牌目录：重写主查询，去掉 `case_brands` 关联 ✅

- **文件**：`web/server/utils/public/case-queries.ts`（`brandDirectoryCte` / `findPublicBrandDirectoryPage` / `findPublicBrandDirectoryStats`）、
  `web/server/utils/public/query.ts`（`buildBrandDirectoryFilterSql`）、`web/server/api/public/brands.get.ts`
- **原问题**：`SELECT` 已补 `cover_url / ip_category / brand_owner`，但 `FROM` 仍关联 `case_brands`，
  而采集已不再写该表，导致 `plaintiff` / `lawFirm` 空、`case_count` 恒为 0、`case_types` 空。
- **实现**：
  - 抽出 `entityCaseMatchSql()`：英文主干双向包含或前 6 位相同、中文去空格双向包含、品牌别名、律所简称，
    目录 / 详情 / 关联案件数共用同一份规则（别名可配，避免 `e.` / `b.` 混用）。
  - 用 `LOCATE` 代替 `LIKE`：大小写仍不敏感，但名称里的 `%`/`_` 不会被当成通配符。
  - 品牌目录改为 `WITH brand_case → brand_agg`：两侧先按不同文本去重物化，匹配范围从
    「1695 品牌 × 2023 案件」降到「1695 × 约 690 种品牌文本」，再一次性聚合出
    案件数、侵权类型、最新案件的原告 / 律所 / 州。
  - 分页与总数合并为一条查询（`COUNT(*) OVER ()`），只有页码越界时才补查一次总数。
  - 关键词在案件号 / 律所上的命中改在聚合阶段标记 `keyword_hit`；侵权分类用 `FIND_IN_SET(?, agg.case_types)`。
  - 品牌 / 律所详情页的关联案件也改用文本匹配（原先读空的 `case_brands` / `case_law_firms`）。
- **实测**（本地库 1695 品牌 / 2023 条已发布案件）：`/api/public/brands` 约 1.0–1.2s，
  统计接口 0.95s；`?caseType=copyright` → 137 个品牌；`?keyword=Toyota` → 1 个品牌；
  `?page=999` 正确夹到最后一页；`/api/public/brands/brand-31` → 50 条案件。
