# 产品侵权检测提交与后台记录设计

## 目标

将“产品侵权检测”页面从仅在浏览器内校验改为真实提交：服务端校验表单并把记录保存到新数据库 `daxin`；后台提供受权限保护的分页记录列表。移除“当前仅进行本地必填校验，不会提交或保存填写的信息。”，并修正隐私说明，使其符合实际数据处理方式。

## 用户可见行为

- 访客填写品牌名称、产品名称、联系人、电话或微信，以及可选备注后提交。
- 客户端继续提供即时必填校验；提交时显示处理中状态并阻止重复点击。
- 服务端校验通过并写入数据库后，页面明确显示已提交；服务端拒绝或写入失败时显示可理解的错误，表单内容保留供用户修正或重试。
- 成功后允许用户重新填写一条记录。
- 隐私说明改为说明上述提交字段会保存至网站数据库，并由有权限的后台管理员用于联系与处理检测申请。表单内容不返回给公开查询接口，也不写入应用日志。

## 数据与接口

### 数据表

在 `database/migrations/019_product_infringement_checks.sql` 创建 `product_infringement_checks` 独立表，不修改旧库 `da` 或现有业务表。字段：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | `BIGINT UNSIGNED` | 主键、自增 |
| `brand_name` | `VARCHAR(120)` | 必填，保存去除首尾空白后的品牌名称 |
| `product_name` | `VARCHAR(160)` | 必填，保存去除首尾空白后的产品名称 |
| `contact_name` | `VARCHAR(80)` | 必填，联系人 |
| `contact_method` | `VARCHAR(120)` | 必填，电话或微信 |
| `remark` | `TEXT` | 可选备注；空值存为 `NULL` |
| `created_at` | `DATETIME` | 数据库写入时间 |

使用 InnoDB、`utf8mb4`；以 `(created_at, id)` 支持新记录优先的列表排序。表中不保存原始 IP、用户代理或其他未要求的追踪数据。迁移只创建表，不清理或改写既有数据。

### 公开提交

- `POST /api/public/infringement-check` 接收 JSON 表单。
- 服务端重复执行必填和长度校验；不信任浏览器校验。空白字符串按空值处理，备注最多 2,000 字符；超限或字段非法返回 `400`。
- 通过参数化 SQL 写入专用表；成功返回 `201` 和不含个人信息的成功状态。不得把表单值写入日志或错误响应。
- 不提供公开列表、详情或查询接口。服务端数据库异常返回通用错误，不向访客暴露 SQL 或内部配置。

### 后台分页查询

- `GET /api/admin/infringement-checks?page=&pageSize=` 返回 `data` 和 `meta`，复用现有 `resolvePageWindow` 分页规则及后台页大小档位 `10 / 20 / 30 / 40 / 50`，默认 20、上限 50，超出末页按现有规则夹取。
- 列表按 `created_at DESC, id DESC` 排序，返回提交时间、品牌、产品、联系人、联系方式和备注。
- 使用独立权限 `product_infringement_check:read`；仅管理员角色可读。公开接口不会复用后台鉴权，后台接口不接受访客访问。
- 第一版只读，不增加编辑、删除、导出、状态流转或额外筛选。

## 后台页面

- 新增 `/admin/infringement-checks` 页面并在后台左侧菜单增加“产品侵权检测”；仅管理员显示菜单。
- 复用后台列表加载、错误提示、空状态和 `AdminPager`，支持服务端分页及每页条数切换。
- 桌面端以表格呈现字段；备注允许换行，窄屏可横向滚动或改为卡片布局，避免长文本挤压联系方式。
- 页面不显示无关状态、编辑或删除控件。

## 安全与隐私

- 该表包含联系人及联系方式，后台列表限制为管理员；接口执行服务端权限校验。
- 所有写入与查询使用绑定参数；记录内容不会拼入 SQL、URL、审计日志或服务端日志。
- 不把用户提交值回显到公开页面之外；成功响应只表达提交结果。
- 首版不设置自动过期或删除策略，以满足后台可分页查阅的需求；记录持续保存在专用表中，后续如需保留期限或后台删除能力，另行设计。

## 验证

- 单元/静态测试覆盖：页面不再出现本地不保存提示；客户端提交调用公开接口并处理等待、成功和失败；公开 API 必填、长度校验及参数化写入；后台 API 拒绝无权限请求并遵循统一分页；导航、后台页和管理员权限一致；隐私说明与数据处理一致；迁移只创建新表。
- 运行项目现有 `npm test`、`npm run typecheck`、`npm run check:static`。若本机数据库可用，再应用新迁移并验证成功提交后后台第一页能读到记录；不会运行任何清空或删除数据的语句。

## 范围外

- OSS/图片上传、侵权分析自动化、邮件或短信通知。
- 修改现有文章、案例、品牌、律所数据。
- 管理员编辑、删除、导出、分配或处理状态。
- 公开查询提交记录。
