# 后台用户与权限管理设计

## 目标

将现有 `/admin/users` 占位页替换为可用的后台账号管理页面。管理员可以查看、筛选、新建、编辑、重置密码、启用/停用和删除后台账号；本次不提供邮箱字段。

## 范围

- 前端页面：`web/app/pages/admin/users.vue`。
- 使用现有接口：`GET/POST /api/admin/users`、`PUT/DELETE /api/admin/users/:id`。
- 使用现有角色：`admin`、`editor`、`viewer`。
- 用户名创建后不可修改。
- 新建和编辑表单包含用户名（编辑只读）、显示名、密码、角色、状态；不包含邮箱。
- 删除账号前要求确认。
- 服务端已有的权限、最后一个管理员、自身账号保护规则继续作为最终约束。
- 不新增数据库表、迁移或 API。

## 页面设计

### 列表

页面标题为“用户与权限”，右侧提供“新建账号”。列表上方提供关键词、角色、状态筛选，以及查询和重置按钮。

列表字段为：用户名、显示名、角色、状态、最近登录、创建时间、操作。邮箱不出现在列表、表单、接口请求体或页面文案中。

### 表单

新建和编辑共用一个侧边表单面板。新建时显示用户名、显示名、初始密码、角色、状态；编辑时用户名只读，密码改为可选的“新密码”，留空表示不修改。角色使用固定选项的多选控件，状态使用启用/停用下拉框。

### 反馈与安全

- 加载、保存、删除期间显示明确状态并避免重复提交。
- 接口返回的中文错误直接展示。
- 删除使用确认对话框。
- 非管理员不会在导航中看到入口；页面和接口仍由服务端鉴权保护。
- 前端不保存或展示密码，不把密码写入日志或成功提示。

## 数据流

页面加载或筛选时调用 `GET /api/admin/users`。新建调用 `POST`，编辑调用 `PUT /api/admin/users/:id`，删除调用 `DELETE /api/admin/users/:id`。写操作成功后重新加载列表，确保显示数据库中的真实状态。

## 验证

- 增加静态回归测试，确认用户页使用现有用户 API、没有邮箱字段、包含角色和状态控件。
- 运行 `npm run test` 和 `npm run typecheck`。
- 运行开发服务器后检查 `/admin/users` 页面能渲染列表入口；未登录时仍跳转登录页。
