# 侧边栏与首页普法干货配置设计

## 背景与目标

官网内容页侧栏目前把常见问题、联系二维码、说明文字和电话写在组件中；首页“普法干货”轮播也把三本书的图片、标题和正文写在组件中。此次改造让侧栏内容与首页书本内容可由后台维护，并按用户确认的布局展示。首页团队介绍右侧的四个业务块已经通过 `service_sections` / `service_items`、`/admin/services` 和公开首页接口实现配置化，本次保留并复用，不增加第二套配置。

## 已确认的展示规则

- 内容页侧栏先显示“常见问题”，再显示二维码区域。
- 二维码区依次显示标题“关注公众号了解咨询”和“添加咨询号沟通案件”，每个标题下显示对应的二维码。
- 移除侧栏原浅色说明文字、二维码下方的名称或提示文字，以及电话咨询入口。
- TRO 内容页使用 TRO 公众号与 TRO 咨询号；劳动法内容页使用劳动法公众号与劳动法咨询号。
- `group="all"` 的侧栏默认使用 TRO 公众号与 TRO 咨询号，作为跨主题内容的兜底展示。
- 首页“普法干货”保留 TRO、劳动法、国际物流三本书及现有五秒自动轮播。图片、标题、正文、领取说明及主题色改为后台可配置；二维码继续引用现有二维码资源配置。
- 业务块继续从现有服务配置读取；后台 `/admin/services` 仍是唯一编辑入口。

## 方案评估

### 方案 A：扩展现有 `site_settings` 与二维码配置（选定）

使用现有 `site_settings` 的 JSON 配置存放侧栏与普法干货数据；公众号二维码继续使用 `footer_qr_primary` / `footer_qr_secondary` 图片配置，咨询号二维码继续使用 `qr_assets`；业务块继续使用 `service_sections` / `service_items`。通过迁移添加默认配置行，通过已有站点设置读写接口和后台页面提供结构化编辑器。该方案沿用权限、保存、发布状态、图片上传及公开配置接口，且不增加数据库表。

### 方案 B：为侧栏和每本书新建关系表

为轮播页、段落、侧栏 FAQ 等分别建表并开发专用接口。数据关系更显式，但会重复现有 key-value 配置和内容管理能力，增加数据库迁移和维护面，当前规模不需要。

### 方案 C：在前端保留默认文案，只允许后台覆盖部分字段

改动较少，但配置缺失或更新时可能出现后台与线上默认内容不一致，且配置字段不完整，不适合本次“可配置化”目标。

## 推荐架构与数据结构

### 侧栏配置

在 `site_settings` 中新增 JSON 配置 `content_sidebar`（`setting_group='general'`，后台归入“站点信息”）。建议结构：

```json
{
  "faqTitle": "常见问题",
  "faqLinks": [
    { "key": "tro", "label": "TRO 常见问题", "path": "/faq/tro", "enabled": true, "sortOrder": 10 },
    { "key": "labor", "label": "劳动争议", "path": "/faq/labor", "enabled": true, "sortOrder": 20 },
    { "key": "cross-border", "label": "跨境干货", "path": "/faq/cross-border", "enabled": true, "sortOrder": 30 }
  ],
  "publicHeading": "关注公众号了解咨询",
  "consultHeading": "添加咨询号沟通案件"
}
```

侧栏按当前 `group` 过滤 FAQ：TRO 页面隐藏劳动法入口，劳动法页面隐藏 TRO 入口，`all` 页面显示全部已启用入口；链接仍限于站内路径。公众号二维码复用站点设置中的 `footer_qr_primary`（TRO）和 `footer_qr_secondary`（劳动法）；咨询号二维码从 `qr_assets` 的公开配置映射取得。图片不重复写入 `content_sidebar`，以免出现两处图片来源。

### 首页普法干货配置

在 `site_settings` 中新增 JSON 配置 `home_legal_guides`（`setting_group='home'`，后台归入“首页文案”）。配置为有序主题数组，每项包含 `slug`、`category`、`title`、`paragraphs`、`image`、`imageAlt`、`benefit`、`accent` 和 `qrItemKey`。保留 TRO、劳动法和国际物流三个主题及现有顺序；`qrItemKey` 分别引用 `qr_assets` 中的 `qr-tro-consult` 和 `qr-labor-consult`，物流主题可以不配置二维码。

后台编辑器提供三个固定主题槽位（TRO、劳动法、国际物流），各槽位可编辑标题、分类名、正文段落、领取说明、主题颜色、图片及替代文字；正文段落可增删。主题标识和轮播顺序固定，避免管理员误删主题后轮播索引失效。图片使用当前 OSS 上传能力，最终 URL 随 JSON 保存。配置解析失败时保留页面原有默认轮播内容，并阻止后台将损坏 JSON 覆盖保存。

### 业务块与二维码

- 四个团队业务块保持现状：后台 `/admin/services` 写入 `service_sections` 和 `service_items`，公开首页接口读取后传给 `HomeTeamServices`。
- 咨询号二维码仍通过现有“页脚与联系方式”中的二维码管理写入 `qr_assets`，公开配置接口的 `footer.qr` 按 `itemKey` 提供图片目录；公众号二维码继续通过“站点信息”中的 `footer_qr_primary` 与 `footer_qr_secondary` 图片配置维护。侧栏或主题引用不存在、停用或无图片的二维码时，显示现有静态默认图片，保证页面可用。

## 数据流

1. 数据迁移插入 `content_sidebar` 与 `home_legal_guides` 的当前配置行，只有不存在当前行时才创建，避免覆盖管理员已有配置。
2. 后台站点设置使用现有 `GET/PUT /api/admin/settings`，增加两个 JSON 结构化编辑器，并复用现有角色权限、草稿/发布状态和保存错误处理。
3. 公开设置接口继续读取已发布的 `site_settings` 和 `qr_assets`，输出解码后的设置及咨询号二维码目录。
4. `ContentSidebar` 读取 `content_sidebar`、公众号图片配置及咨询号二维码目录，按照页面 group 选择两个二维码并渲染 FAQ 在前、二维码在后的布局。
5. `HomeLegalGuides` 读取 `home_legal_guides` 和咨询号二维码目录，轮播时使用已配置主题；数据缺失或不可解析时回退到组件内当前默认值。
6. 团队业务块数据流不变，继续由公开首页接口和现有管理页维护。

## 错误处理与兼容性

- 新配置缺失、空数组、字段类型不合法或 JSON 解析失败时，前台继续显示当前已有默认数据，不因配置故障隐藏整个栏目。
- 后台解析 JSON 失败时登记阻断错误，禁止提交该配置，避免覆盖原始值；保存后重新拉取服务端数据以更新基线。
- 咨询号二维码按稳定 `itemKey` 匹配；公众号或咨询号未找到可用图片时采用对应静态二维码兜底。
- FAQ 路径只接受以 `/` 开头的站内路径，标签和正文按普通文本渲染，不解释为 HTML。
- 轮播配置固定包含现有三个主题，不能通过后台删除或重排；若主题数据不完整，前台回退到完整默认轮播，保证切换索引不会越界。
- 不新增关系表，不改现有业务块配置或权限模型。

## 验收标准

1. TRO、劳动法、`all` 三种侧栏均先显示 FAQ，再显示两个标题及匹配二维码；没有浅色说明、二维码下标签或电话。
2. 后台可编辑侧栏标题及 FAQ 项的名称、站内链接、显示状态和顺序，保存后公开页面更新。
3. 后台可编辑三个普法主题的图片、标题、正文、领取说明和主题色，保存后首页轮播更新；图片可通过现有 OSS 上传控件上传。
4. TRO/劳动法主题使用对应咨询二维码，二维码仍可从现有二维码管理更换；公众号图片继续使用现有页脚公众号配置；物流主题支持暂不配置二维码。
5. 四个团队业务块仍由 `/admin/services` 管理并正确显示，不出现重复配置入口。
6. 无新增数据库表；迁移重复执行不会覆盖当前配置。
7. 类型检查、相关单元测试及 Nuxt 构建通过；验证公开接口输出与前台实际展示。

## 实施范围外

- 不改页脚布局和页脚文字。
- 不改关于我们文案、二维码或页面结构。
- 不改业务块标题、内容或跳转行为。
- 不重做已有 `/admin/sidebar` 文章侧栏管理（其职责与内容页 FAQ/二维码侧栏不同）。

## 固定约定

- FAQ 配置只编辑固定的三个站内入口，不开放任意外链。
- 轮播编辑器提供 TRO、劳动法、国际物流三个固定主题，不开放增删或重排。
- 对没有上传自定义公众号二维码的情况，沿用现有 `footer_qr_primary` / `footer_qr_secondary` 配置并使用静态兜底；咨询号可从已有二维码管理页面替换，无需重复上传入口。
