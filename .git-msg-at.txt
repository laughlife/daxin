## 字段顺序（迁移 009）

原先 settings.get.ts 用 `ORDER BY s.setting_key`，即**按字母序**，
与页面实际顺序无关（例如首页先显示 badge 再 title，字母序却把 title 排在前面）。

改为新增 `site_settings.sort_order` 列并 `ORDER BY sort_order, setting_key`
（第二关键字保证同值时的确定性）。

**为什么把顺序放数据库而不是前端常量**：排序属于「这组配置怎么展示」的数据属性，
放库里边可直接调整、无需改代码发版；前端硬编码则会出现
「库里新增了键但前端漏配顺序」的静默问题。

取值依据各页面模板中字段出现的先后：

- **home**：badge → title → subtitle → 主按钮文案 → 主按钮链接 → 次按钮
  → Banner 图 → 团队右侧图 → 数据概览
- **about**：欢迎语 → 公司名 → 简介正文 → 首图 → 团队标题 → 团队段落 → 联系标题
  → 业务图 → 成功案例标题 → 成功案例图 → 宣讲标题 → 宣讲图 → 小伙伴标题 → 小伙伴图 → 荣誉图
- **site**：名称 → logo → 副标题 → 描述 → 电话 → 邮箱 → 地址 → 微信
  （后四项与页脚「联系我们」从上到下一致）

同时为该组查询加了索引 `idx_site_settings_group_sort`，并按项目约定放进
`@if-index-missing` 条件块。

## 删除 about_success_category

该键前台从未渲染（成功案例区块早已按旧站改为图片列表，不再按文章分类取数），
用户确认删除。同步移除 `aboutContent.ts` 里的 `successCategory` 字段
（类型、DEFAULTS、读取逻辑三处），不留悬空引用。软删除，可恢复。
